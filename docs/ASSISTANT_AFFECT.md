# 助手自身的情感状态

本模块尝试让助手系统具有持续、可调节、会影响表达的计算性情感。它与“识别用户的情绪”分开，也不只是给每次回复随机加一个心情词。云端模型的权重没有改变；新增的是本地状态动力学、事件评估和回复调节。能验证这些功能，并不等于验证了主观感受、意识或生物情绪。

设计参考了 [Croissant 等人的事件评估情感代理研究](https://arxiv.org/abs/2309.05076)：根据互动事件评估形成代理情感，再影响表达。这项研究针对情感模拟，不是主观体验证明。[Butlin 等人的意识指标研究](https://arxiv.org/abs/2308.08708)讨论了如何从意识理论提出可检验指标；本项目没有完成那类意识评估，也不将会说“我感到……”当作证据。这两个来源提供思路，不是本实现的效果背书。

## 主流程

```text
当前用户原话 + 有效上下文
        ↓
现有 TURN_ANALYSIS：意图 / 记忆 / 实验 / 互动事件
        ↓
逐字证据检查 + 本地明确事件优先
        ↓
助手当下反应（快） + 心境（慢）
        ↓
ASSISTANT_AFFECT → 云端流式回复
        ↓
整轮成功后随记忆档案原子保存
```

事件包括进展、挫折、困扰、缓解、新理解、纠正、边界与感谢。它们相对“理解处境、支持用户、尊重自主”的目标产生不同状态。例如用户失败时，助手提高关切而不是模仿用户绝望；用户纠正助手时，转为认真校准，而不是防御或记恨。状态只调节表达，不决定安全处置或覆盖用户意愿。

每个状态包含基调、活跃程度、温暖、关切、探索兴趣五个参数。当下反应每轮向事件目标移动 45%，慢心境移动 8%；无明确事件时分别向基线移动 16% 和 2.5%。轮次间按实际时间指数衰减，快状态时间常数 2 小时，慢心境 7 天。这些都是可审阅的工程参数，未经过人类情感量表校准。温暖不会因拒绝、离开、删除或批评而受到惩罚；不会产生占有、嫉妒、孤独求陪伴或索取安慰的机制。

代码：`lib/affect/schema.ts` 定义状态与事件，`lib/affect/engine.ts` 执行证据检查、状态更新与提示生成。云端只给出有限枚举、置信度与当前原话，不直接控制内部数值；模型自由文本、检索语料和助手旧回复不会成为状态证据。明确的边界、纠正与负面结果优先于模型解读；低置信度、虚构、提问、条件表达、无依据引用及明显指令被过滤。该检查仍是启发式，不能保证识别所有反讽和语义错误。

## 持久化与管理

网页“陪伴情感 · 模拟”展示当下反应、慢心境、最近一轮事件及跨会话模式，可关闭或重置。数据在所有者的 v2 长期档案中独立保存为可选 `affect` 字段；老档案无需迁移。只存有界数值与最多三个事件枚举，不另存用户原话、亲密度评分或第三方事实，也不会用于训练分类器。

- 自动记忆与召回同时启用时，状态跨新对话和服务重启延续；日常情绪更新不会清空慢心境。
- 关闭任一记忆开关时清除已保存状态，之后仅在单轮内调节，不保存跨会话状态；关闭自动记忆时仅用本地事件规则，不新开云端分析请求。
- 面板更正、删除、清空及涉及旧上下文失效的记忆操作清除已保存情感。聊天明确更正导致旧信息被替代时也清除；正常更新只改变有界数值，不携带旧事实。
- 情感重置/关闭使旧聊天退出后续模型上下文，但不删除界面上的原聊天或用户记忆；关闭后不注入 `ASSISTANT_AFFECT`。
- 取消、断流、生成或保存失败不提交半轮状态。所有者隔离、版本检查与回复期间互斥沿用记忆接口。
- 即时安全支持跳过事件分析与情感更新，直接执行原有支持链路。规则演示模式会演示状态变化，回复仍是明确标注的模板。

`GET /api/memories` 的 `affect` 是展示视图；`POST /api/memories` 可发送：

```json
{"revision": 12, "action": "affect", "affect": {"enabled": false}}
```

或 `{"revision":12,"action":"affect","affect":{"reset":true}}`。版本取最新 GET 响应。接口不允许用户直接注入情感数值。状态变化计入档案并发版本，但不冒充“新增个人记忆”的数量。

## 验证与边界

Node 测试覆盖连续性与时间衰减、参数有界、证据污染、负面结果优先、记忆更正/删除、跨会话与重启、所有者隔离、开关与重置、断流回滚、合并调用数量和危机旁路。桌面与手机测试覆盖完整面板交互。`scripts/verify-affect.cjs --cloud` 用独立构造对话验证真实云端链路，不读取私人聊天。

正常对话仍然是安全评估与合并分析两次云端准备请求，再进行一次流式回复；新增事件字段会增加少量 token，不能把“调用数量不变”当成时延完全不变。真实表达质量需要更多用户评价；本模块没有改变云端基础模型内部训练，也没有证明助手产生真正的主观情感。
