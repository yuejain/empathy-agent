# 性能诊断、模块补齐与部分 Python 迁移

验收日期：2026-10-14。基线为 `0f78ec4`（随后合并到 `66c1cb7`，文件内容相同）。本轮检查了 HTTP/SSE、准备请求、持久化、RAG 热路径、前端流式更新和模块可达性。所有基准使用构造输入及独立档案，不读取用户聊天，也不调用真实云端。

## 实测瓶颈与改动

| 范围 | 诊断 | 实现 |
| --- | --- | --- |
| 持久化 | 每轮同步序列化、重写全部 JSON；档案增多后阻塞事件循环 | 写操作改为串行异步事务；新增 Python SQLite 差量提交，只发送本次变更；持久化成功才发布内存状态 |
| Python 检索 | 每轮重复构造公开文档词项/情绪集合并全量排序 | 不可变公开索引预计算、向量化筛选、分组取前三；用随机及实际索引比对排序一致性 |
| 热加载与并发 | 更新瞬间可能重复加载模型/索引；编码请求无限等待 | 同时只执行一次刷新，500ms 检查间隔；最多 4 个在途推理，锁等待 8 秒，过载显式降级 |
| 编码 | 80 条个人记忆时仍由编码主导 | 请求内去重，不跨请求缓存个人向量；不将分类/排名分数冒充情绪强度 |
| 前端流式 | 每个分片替换整段文字并滚动，造成重复 DOM 操作 | 每帧合并后增量追加；完成时以已保存文本收束，停止/错误取消待执行更新；用户上翻时不抢滚动位置 |
| 静态资源 | 启动已读入内存，但每次仍全量传输 | 内容 ETag 与条件 304；私人 API 保持 `no-store` |
| 编排 | 准备阶段已有并行，继续换语言不能消除云端等待 | 保留两次准备加一次生成；去掉重复词典识别，统一分类标签与策略 ID；新增持久化阶段计时 |

## 同权限配对测量

Windows / Node v24 / Python 3.11。同一台机器、相同模拟服务延迟；旧运行代码冻结到独立目录。每个 HTTP 场景预热一次，再测 12 轮；吞吐为 4 个独立所有者、各 3 轮。场景开始前显式 GC，不在请求内强制回收。200 个档案各含 80 条合成记忆，输入 JSON 约 13.10 MB。

以下保留第一组受控配对与启动缓冲优化后的最终复测。原始报告在被忽略的 `artifacts/performance/before-gc.json`、`after-sqlite-gc.json` 和 `final-sqlite.json`：

| 指标 | 旧同步 JSON | 首轮 SQLite | 最终 SQLite |
| --- | ---: | ---: | ---: |
| 1 个档案提交 p50 | 1.768 ms | 2.302 ms | 2.221 ms |
| 50 个档案提交 p50 | 12.460 ms | 2.334 ms | 2.111 ms |
| 200 个档案提交 p50 | 43.567 ms | 2.687 ms | 1.991 ms |
| 200 个档案首段 p50 | 72.359 ms | 73.318 ms | 68.234 ms |
| 200 个档案整轮 HTTP p50 | 188.848 ms | 112.147 ms | 103.636 ms |
| 200 个档案事件循环延迟 p95 | 90.702 ms | 13.173 ms | 12.214 ms |
| 200 个档案、4 并发吞吐 | 8.828 请求/秒 | 27.728 请求/秒 | 34.550 请求/秒 |
| 无持久化控制场景整轮 p50 | 99.095 ms | 107.294 ms | 101.725 ms |

最终大档案提交减少约 95%，模拟整轮减少约 45%；首段只有小变化，云端等待未减少。小档案提交略慢，无持久化控制场景首轮慢约 8%、最终约 2.7%，不能说所有场景都更快。独立异步 JSON 对照整轮为 191.257 → 199.139 ms，没有端到端收益：全量序列化仍在主线程。

最初 SQLite 的 200 档案冷迁移/重启约 1515/1271 ms，旧 JSON 约 145/125 ms。针对启动管道重复扫描增加了分片解析后，最终 SQLite 为 758/329 ms，仍慢于旧 JSON。SQLite 需要启动解释器、读取并校验全量档案，不能承诺启动更快。

这些数值只代表本机合成负载，12 个样本的 p95 接近最大值；不用于推断真实云端速度、统计显著性或生产容量。RSS/heap 是同进程快照，混有夹具与 GC，不能据此声称消除泄漏。基线遇到的 Windows `EPERM` 重命名失败保留在失败报告；新 JSON 写入做有限重试，最终失败仍不发布内存状态。

| 检索阶段 | 旧中位 | 新中位 |
| --- | ---: | ---: |

## Python 存储的使用与迁移

在 `.env` 设置后重启网页服务：

```dotenv
SESSION_PERSISTENCE=true
SESSION_STORAGE=sqlite
# 可选；默认先查本项目 .venv-ml，再用 PATH 中的 python
# PYTHON_EXECUTABLE=C:/path/to/python.exe
```

只需 Python 3.11 标准库，不需要安装 Torch、运行 RAG 服务或下载模型。Node 负责 HTTP/SSE、领域校验和所有者隔离，`server/python-storage.ts` 通过本地管道连接 `ml/session_storage.py`；存储进程不监听网络，也不继承云端密钥。

首次启动校验现有 `sessions.json`，将会话及用户档案在同一 SQLite 事务内导入 `sessions.sqlite3`。v1 迁移仍将旧记忆放入待核对，并保留原始备份。数据库初始化后成为唯一来源，即使档案已清空或旧 JSON 损坏，也不会重导旧数据。旧 JSON 保留为迁移备份，不双写、不自动擦除；之后直接切回 JSON 会被拒绝，避免恢复已遗忘内容。

SQLite 使用 WAL、完整同步和一个进程独占租约；第二个实例必须使用不同数据目录。服务停止后再复制数据目录作备份；运行时 WAL/SHM 也可能包含未完成检查点的数据，不能仅复制主数据库。这些行为依据 [Python sqlite3 事务接口](https://docs.python.org/3.11/library/sqlite3.html#how-to-use-the-connection-context-manager) 和 [SQLite WAL 文档](https://sqlite.org/wal.html)。

JSON 与 SQLite 都是**未加密本机存储**。数据库、WAL、备份与锁文件均不能公开；删除是应用层删除，不承诺取证级擦除历史备份。进程失败或提交确认丢失时不会静默降级到旧 JSON，应重启后读取数据库确认最终状态。构造、加载和迁移时需要完整校验；此方案仍不是多用户数据库服务或跨设备同步。

推理及提交排队期间停止会取消该轮。原子持久化开始后，已经完整生成的回复可能完成保存；不会保存只有半段文本的回复。revision 在写入队列内重新校验，读请求只看已确认提交的快照。

## 复现与验证

本轮 103 项 Node、34 项桌面/手机浏览器、34 项 Python 测试通过，共 171 项。包括启动端口占用后退出、存储队列取消、事务失败回滚、迁移后删除不复活、独占租约、模型排序一致性、子意图调用数量与流式终止。浏览器的 800 个分片突发用例验证消息文本 DOM 修改不超过 4 次；这是固定夹具的操作次数，不是帧率测量。未重复调用真实云端，服务商速度与回答质量不在本轮结论中。

```powershell
npm test
npm run test:browser
.\.venv-ml\Scripts\python.exe -m unittest discover -s ml -p 'test_*.py'
node --expose-gc scripts/benchmark-system.cjs --label json
node --expose-gc scripts/benchmark-system.cjs --label sqlite --backend sqlite --python .venv-ml/Scripts/python.exe --compare artifacts/performance/json.json
.\.venv-ml\Scripts\python.exe ml/benchmark_rag.py --samples 20 --real
```

系统基准不加载 `.env`。RAG 基准的 `--real` 指本机已下载的编码器和公开索引，不是云端调用；不加该参数可只测构造索引。`--runtime` 可指定冻结的旧 dist 作真正版本对照；上面的 json/sqlite 命令比较的是当前两个后端。所有原始产物在 Git 忽略目录，测试不以脆弱的墙钟阈值判定通过。


## 300 条候选的成本（2026-10-18）

为修复旧记录在语义评分前被截断的问题，本轮将候选上限从 80 扩至所有者全部有效记录（最多 300），未降低最终 6 条/1,800 字符的云端预算。固定双语召回用例及误召回见 [效果评测](EVALUATION.md)。这是覆盖升级，不是编码提速。

同机 CPU、真实本地编码器、每档一次预热及五次样本，使用互不相同的短英文构造记忆，0/80/300 条分析中位分别为 11.14/164.87/560.61 ms，p95 为 11.80/199.67/584.68 ms。四个并发请求的 80/300 条吞吐分别为 4.356/1.437 请求/秒。不能外推到 300 条每条 500 字的长文本、真实云端首字或生产并发容量；现有本地超时及显式降级继续适用。

`artifacts/evaluation/memory-cost.json` 保存原运行聚合值的测量摘要，未保留逐样本原始耗时，文件已明确标注这一限制。可重新执行 `.venv-ml/Scripts/python.exe ml/benchmark_rag.py --samples 5 --real` 得到包含逐样本值的新报告；不同环境及运行负载会改变结果。
