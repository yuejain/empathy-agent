# 双语效果评测与发布边界

本轮建立了可复现的**合成回归评测**，并使用当前本机真实编码器和分类头测量结果。它能暴露代码回归、多标签过召回和检索漏召回，不能证明中文或英文在人群中的可靠性。没有新增人工标注，没有用评测结果重新训练、挑选阈值或修改判断答案，也没有访问云端模型、`.env` 或私有 `.data`。

## 冻结协议

- [双语 fixture](../evals/fixtures/bilingual-quality-v1.json)：52 条分类用例，中英文各 26 条，覆盖固定 8 类及否定、混合情绪；16 条合成参考文档（8 个主题的中英版本）；20 条公共检索查询，中英文各 10 条，其中各有 2 条无答案查询。
- 全部文本与标签均为 `synthetic-agent-authored`，`human_reviewed: false`。这是开发者构造的回归判断，不是独立人工语料或新的真实用户数据。
- fixture SHA256：`96a58f5af6a2f8c63b61f3ff23dce23d49e5a2e18e9683b4ab9b050550e769d1`。在运行模型前校验冻结哈希；修改判断需显式建立下一版，不能悄悄替换当前答案。
- 分类阈值固定为 0.5，macro-F1 始终对完整 8 类计算。Brier 为所有“样本×标签”二元概率的均方误差；ECE 对同样的二元概率使用 10 个固定等宽箱。二者衡量概率误差，不是准确率；聚合值可能掩盖个别标签的问题。
- 公共检索使用生产 `PublicIndex.search`、真实本地 encoder 和分类头，但库是上面的受控合成库。以主题分组评估 Recall@3 / MRR，避免把同一文档的中英版本重复计分。无答案查询不进入 Recall/MRR 分母，单独统计错误响应率；所有返回结果同时统计误召回与禁止项命中。
- 额外报告“真实情绪标签提示”的公共检索对照，区分分类提示与排序影响；这不是上线时可获得的信息。
- 私有记忆使用[冻结记忆 fixture](../evals/memory-retrieval.json)及[Node 生产路径适配器](../evals/evaluate-memory.cjs)。Python 只对构造文本计算真实语义分数，Node 执行候选选择和最终排名，覆盖旧记忆、跨语言、撤回、过期、删除和关闭召回。不会读取真实档案，也不会保存私有向量。
- [情感重放](../scripts/evaluate-affect.cjs)是确定性合成事件序列检查。它衡量状态更新与表达约束，不能证明主观情感、临床效果或真实关系质量。

## 候选分类头发布门槛 v2

[候选训练](../ml/train_classifier.py)仍能训练并保存候选及报告；[模型注册表](../ml/model_registry.py)只在以下冻结工程政策全部满足时允许发布：

1. `validation/zh/human` 和 `validation/en/human` 两个分区都存在，每个至少 100 条，8 类每类至少 5 个正例。来源由现有语料管道的标注来源及验证分区筛选，不接受合成评测的 `human_reviewed` 自声明替代。
2. 候选与基线必须有相同样本数、标签覆盖和样本内容/标签哈希；来源、语言、分区和校准方法必须完整且相同。
3. 每语言 macro-F1 ≥ 0.40，ECE ≤ 0.15，Brier ≤ 0.20；候选 macro-F1 不下降，ECE/Brier 不增大。所有指标必须是有限数且在 [0,1]，布尔值不当作数字。
4. 测试分区仅作报告；合成、弱标签、缺失中文、空报告、无效报告均不能通过。发布时重新核对证据，不能只把 `passed` 改为 true。
5. 不带 `--candidate` 的旧训练命令只允许首次安装；存在 encoder、head 或活动指针时拒绝直接覆盖。`publish('legacy')` 也拒绝作为新候选发布，已存在的历史版本仍可通过明确回滚恢复。

这些数值是**预先固定的工程准入政策**，不代表统计样本量已经充分，也不是经过实证验证的情绪产品质量标准。当前缺少足量现代中文人工验证，因而新候选应保留为未通过状态；已有活动模型继续运行，不把本次合成结果追认为合格证据。生产检索的人工相关性与脏记忆引用质量仍须另行验证，分类头门槛不能替代端到端发布审查。

## 运行与校验

轻量 CI 不下载权重，使用解析、指标和伪模型测试：

```powershell
python -m unittest discover -s ml -p "test_*.py"
npm run build
node --test tests/memory-candidate-coverage.test.cjs tests/memory-evaluation.test.cjs
```

真实模型评测需要已安装 ML 依赖、已下载的本地 encoder/head 以及编译后的 Node 模块：

```powershell
npm run build
.\.venv-ml\Scripts\python.exe ml\evaluate_quality.py --memory
python ml\evaluate_quality.py --validate-report artifacts\evaluation\bilingual-quality.json
node scripts/evaluate-affect.cjs --output artifacts/affect-replay.json
```

输出 `artifacts/evaluation/bilingual-quality.json` 和 `artifacts/evaluation/memory-retrieval.json`，保留完整逐例预测、排名、来源和模型指纹；另存 `memory-score-input.json` 供仅修改报告校验器时重放这些合成分数，运行产物不进入 Git。双语报告状态固定为 `regression_only`。严格 [JSON schemas](../evals/schemas/report.schema.json) 与 [校验器](../ml/quality_schema.py)拒绝未知字段、缺失语言、NaN/Infinity、重复 JSON 键、缺例/重复例、修改答案、未知文档和不一致统计，并从逐例预测重算聚合指标。报告结构有效不等于质量达标。

下一步需要独立标注者和现代双语对话，固定训练/验证/测试分组，记录来源、标注分歧与一致性，再开展真实公共库相关性评估及分类校准。当前真实人工训练与评测缺口见 [训练记录](TRAINING_RESULTS.md)。
